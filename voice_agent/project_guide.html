1. The big picture

A voice agent that tests how fast and how right Jev really is

You call a fictional Egyptian telecom from your browser and talk to an AI customer-service agent. Behind that call, every step is timed, so you can test a vendor's speed claim instead of trusting it.

The question

Can a fast decision model like Jev make a voice agent quicker, safer, and still accurate?

The product

A working voice agent for Nabda, an invented company with plans, policies, customers, and outages.

The one sentence to remember: Jev decides, the LLM talks. Jev picks what kind of request this is and what knowledge is needed, then the LLM writes the spoken answer from only that knowledge.

2. What Jev is

Jev answers questions with typed decisions, not text

A normal LLM writes sentences. Jev is a "System One" model from TypeSafe: you give it a state and typed questions, and it returns structured answers with probabilities. It can't write the spoken reply, so it has to work alongside an LLM.

3. The pipeline

From your voice to the agent's voice

Click each stage. Only the voice detector runs on your machine. Speech to text, Jev, the LLM, and the voice all run in the cloud.

Why streaming matters: the agent doesn't wait for the full reply. As soon as the first complete sentence is ready, it goes to the voice, so you hear audio while the rest is still being written.

    5. Three Jev modes

    The hard design problem: order of operations

    To ask "can the knowledge base answer this?", Jev needs to see the knowledge. But the knowledge is chosen from the intent, which Jev also decides. So which comes first? The project has three modes to test the answer, chosen with JEV_MODE.

    The bars show the order of steps and aren't drawn to scale. The live agent uses two_call. A full-turn comparison of the modes was stopped early, so only the numbers shown here are measured.

    6. Knowledge routing

    Jev's decision chooses what the LLM can see

    Pasting the whole company into every prompt would be slow and would burn the free-tier token limit. Instead, the intent picks the files. Click an intent.

    Rules that make routing work on a real call

    • Always included: support_policy.md, because the rules apply to every reply.
    • At most two knowledge files: this keeps prompts small enough for the free tier.
    • Two topics in one question: a second_topic decision loads the main file for each.
    • Follow-ups: "and the night one?" reuses the last answer's file when intent is unclear.
    • Shorter plans file: replies use a trimmed version without repeated fields.
    7. Identity and safety

    The most important safety choice is in the code, not the prompt

    A prompt can be talked around. So a customer's record is simply not given to the LLM until the code has checked the caller's details. With no data in the prompt, there is nothing to leak. Click each stage.

    8. Voice cues

    Giving a text-only model a sense of tone

    Whisper turns speech into words and throws away how you sounded, and Jev can't take audio. So the code measures loudness, pitch, and speed, compares them with earlier in the call, and hands Jev a sentence. Move the sliders: they use the same thresholds as agent/voice_cues.py.

    9. Timing

    Where the time goes in one turn

    These come from your real calls, measured from the moment the voice detector ends your turn.

    Jev's real share

    A routing call took a median of 191 ms on live calls, and the second call 223 ms. Jev is fast, but it isn't the only stage on the path.

    The vendor's claim

    TypeSafe's reported 70 to 500 ms. A single call here: median 190 ms, p95 227 ms, in range from Cairo. Two calls in a row take about 400 ms.

    Stage sizes are differences between medians from 9 to 16 turns, across versions of the agent, so they're a rough picture and not a benchmark. Your brief asked for 20 or more runs.

    What's on the critical path

    Each stage needs the one before it, so speech to text, Jev, the LLM, and the voice run in sequence. Parallel work is used where it's safe: all routing questions go in one Jev request, which answers them together, and logging stays out of the way.

    How to read these fairly

    • The clear win is speed and consistency. Jev's p95 stayed near its median, while the classifier's p95 reached 1,504 ms.
    • The answerable gap isn't a fair fight. In two-call mode, Jev saw the real knowledge file and the classifier only saw a topic list. With the same topic list, Jev scored 90%, against 77%.
    • Sentiment went to the classifier. Jev often read polite "um" and "like" as confused, though some of those labels are debatable.
    • Small differences may be noise. Jev's intent score moved between 79% and 85% between setups.

    Limits to say out loud: Claude Code generated the company data and the labels together, so the labels aren't independent. The test ran before later changes to routing and account checks. The full-turn benchmark was stopped at 2 of 25 turns, so there's no median or p95 for end-to-end speed from replay, and no final-answer pass rate.
